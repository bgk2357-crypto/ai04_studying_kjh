# 장바구니 실험실: 동기와 비동기

쇼핑몰에서 흔히 하는 **상품 정보 / 재고 / 배송 조회**를 FastAPI 앱으로 재현합니다. 기존 `day7`의 FastAPI, asyncio, time, httpx를 사용하며 프런트엔드는 HTML/CSS/JavaScript입니다. Node.js나 외부 API 키가 필요하지 않습니다. 원래 `day7` 파일은 수정하지 않습니다.

실제 상품 API 호출 대신 `time.sleep()`과 `asyncio.sleep()`으로 **I/O 응답 대기**를 흉내냅니다. 결제, DB 저장, 실제 주문은 하지 않습니다.

## 실행 방법 (Windows PowerShell)

Python 3.11 이상을 설치한 환경에서 프로젝트 루트(`C:\AI_04기`)를 기준으로 실행합니다. 아래에서 `python`이 인식되지 않으면 Python 설치 시 PATH 추가를 선택하고 터미널을 다시 열거나, 사용 가능한 `py` 명령으로 대신 실행하세요.

```powershell
cd C:\AI_04기\day7\shop_async_lab
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8001 --workers 1
```

브라우저에서 **http://127.0.0.1:8001** 로 접속합니다. API 문서는 **http://127.0.0.1:8001/docs** 입니다. 종료는 터미널에서 `Ctrl+C`를 누릅니다. 가상환경을 활성화하지 않고 직접 Python을 실행하므로 PowerShell 실행 정책을 변경할 필요가 없습니다.

이미 필요한 라이브러리가 설치된 정상적인 가상환경이 있다면 그 Python으로 `-m uvicorn main:app ...`을 실행해도 됩니다. `.venv`에서 `did not find executable` 오류가 나면 생성 당시 Python 경로가 사라진 것입니다. 이 앱 폴더 안에서 새 가상환경을 생성하거나 `.venv_demo`처럼 새 이름으로 만들어 위 명령의 경로를 바꾸세요. 상위 폴더의 기존 가상환경을 덮어쓸 필요가 없습니다.

**비교는 반드시 단일 worker로 진행하세요.** 여러 worker를 사용하면 health 요청이 다른 프로세스로 전달되어 이벤트 루프 차단이 가려질 수 있습니다. 다른 사용자의 실험이나 별도 탭에서의 조회 없이 한 번씩 실행하면 차이가 명확합니다. 8001 포트가 사용 중이라면 `--port 8002`로 바꾸고 브라우저 주소와 probe의 `--url`도 맞춰주세요.

## 화면 사용 순서

1. 왼쪽 주문 미리보기에서 조회할 샘플 상품을 확인합니다. 작은 화면에서는 상품 미리보기를 숨깁니다.
2. 처리 방식을 선택한 뒤 **선택한 방식으로 조회**를 누릅니다.
3. 조회 중 경과 시간이 표시됩니다. 별도의 health 요청을 조회 시작 약 0.15초 뒤 전송합니다. **서버 응답 확인** 버튼으로도 확인할 수 있습니다.
4. 완료 후 실제 서버에서 측정한 시작·종료 시점, 조회 결과, 전체 시간, health 왕복 시간을 확인합니다. 시간표는 완료 후 표시하며 실행 중 가상의 진행률은 만들지 않습니다.
5. **4가지 모두 비교**는 네 실험을 하나씩 실행하고 기록을 남깁니다. 최신 20개 기록은 현재 탭 메모리에 보관되며 새로고침하면 초기화됩니다. 마지막 실험 결과가 위 시간표에 표시됩니다.

기본 상품/재고/배송 대기는 각각 **1.2초 / 1.8초 / 1.0초**입니다. 대기 시간 옵션은 이 값을 0.5배·1배·2배로 바꿉니다. 모드 카드의 예상 시간은 기본 1배 기준입니다. 아래 숫자는 예상값이며 운영체제 스케줄링, 네트워크 등으로 실제 값이 달라집니다.

| 처리 방식 | 구현 | 전체 예상 시간 (1배) | 다른 요청 처리 |
| --- | --- | --- | --- |
| 동기 · 순차 | 스레드 안에서 동기 함수 3개를 순서대로 호출 | 약 4.0초 | 이벤트 루프에서 계속 가능 |
| 이벤트 루프 차단 | `async def` 안에서 `time.sleep`, `gather`로 묶음 | 약 4.0초 | 이벤트 루프가 막혀 health도 대기 |
| 비동기 · 동시 | `asyncio.gather` + `await asyncio.sleep` | 약 1.8초 | 대기 중 다른 작업 처리 가능 |
| 기존 동기 코드 개선 | `asyncio.gather` + `asyncio.to_thread` | 약 1.8초 | 동기 함수를 스레드로 분리 |

동기와 순차, 비동기와 동시는 같은 뜻이 아닙니다. 이 앱의 첫 번째 모드는 **실제 동기 함수**를 순차로 실행하되 스레드에 맡겨 서버의 이벤트 루프를 보호합니다. FastAPI의 일반 `def` 경로도 스레드풀에서 실행한다는 점과 연결되는 예시입니다. 실제 구현에서는 `asyncio.to_thread()`로 명시적으로 분리했습니다. 반면 두 번째 모드는 이벤트 루프에서 동기 함수를 직접 호출하므로 다른 요청까지 막습니다.

`await`을 세 번 차례대로 쓰면 비동기 함수도 순차 실행됩니다. 여기서는 세 서비스가 서로 독립적이므로 `gather`로 함께 기다릴 수 있습니다. 결제 승인 후 주문 확정처럼 의존 관계가 있는 작업까지 무조건 동시에 실행하면 안 됩니다. 스레드 방식도 스레드 수와 자원에 한계가 있으며, CPU 연산의 속도 향상을 보장하지 않습니다.

## 터미널에서 검증하기

위 서버를 켜둔 상태에서 **두 번째 PowerShell**을 열어 실행합니다.

```powershell
cd C:\AI_04기\day7\shop_async_lab
.\.venv\Scripts\python.exe probe.py
# 다른 포트를 사용했다면:
.\.venv\Scripts\python.exe probe.py --url http://127.0.0.1:8002
```

`probe.py`는 실제 HTTP로 화면 파일, 입력 검증(422), 순차/동시 실행 시간표, 차단 모드의 health 지연을 검사합니다. 이후 고객 3명의 요청을 동시에 보냅니다. 0.25배 기준 차단 모드는 약 3초, 비동기 모드는 약 0.45초가 예상됩니다. 측정값과 마지막 `검증 통과` 출력을 확인하세요. 실행 환경 부하가 큰 경우 시간 차이에 대한 검증은 영향을 받을 수 있습니다.

### 작성 시 검증 결과 (2026-10-22)

단일 Uvicorn worker에서 실제 HTTP 검증을 통과했습니다. 아래는 **0.5배** 대기 시간의 실측값입니다.

| 모드 | 조회 시간 | 조회 중 health 왕복 시간 |
| --- | --- | --- |
| sync | 2.00초 | 4ms |
| blocking | 2.00초 | 1,855ms |
| async | 0.91초 | 7ms |
| thread | 0.90초 | 7ms |

고객 3명 동시 요청(0.25배)은 blocking 3.02초 / async 0.47초였습니다. JavaScript 구문 검사도 통과했습니다. 연결 가능한 브라우저가 없어 실제 브라우저에서의 화면 배치 및 클릭 동작은 확인하지 못했습니다.

## 파일 구성

```text
shop_async_lab/
├── main.py            # FastAPI, 네 가지 처리 방식, health API
├── probe.py           # httpx 실측·검증 클라이언트
├── requirements.txt   # Python 의존성
├── README.md          # 실행·관찰 가이드
└── static/
    ├── index.html     # 쇼핑몰 예제 화면
    ├── style.css      # 반응형 스타일과 상품 일러스트
    └── app.js         # 조회, 별도 health 요청, 결과·시간표
```

코드는 `legacy_lookup` → `blocking_lookup` → `checkout` 순서로 읽으면 차단 원인과 해결 방법을 확인하기 쉽습니다. 기존 `day7/main.py`의 `/bad`는 이미 `asyncio.to_thread()`를 사용하므로, 이름이나 주석과 달리 동기 호출을 직접 실행하는 차단 예제가 아닙니다. 이 앱의 `blocking` 모드가 그 문제를 의도적으로 재현합니다.
